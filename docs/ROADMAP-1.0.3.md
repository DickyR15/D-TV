# D TV 1.0.3 開發規劃

本文件追蹤 `dev/v1.0.3` 的開發範圍、現況與驗收條件。此分支由已發布的 D TV 1.0.2（`main`）建立；開發分支的 CI 會建置及驗證四平台，但不會建立或發布正式 Release。

## 本版目標

1. 修復既有平台問題，避免回歸已穩定的播放與片源功能。
2. 完成 iPhone Duo 的自適應版面驗證。
3. 整理區域網路自動同步體驗，優先確認授權、帳號資料及衝突處理。
4. 先完成 PlaybackSession／雙播放器預載的架構研究與效能驗收，不直接重寫播放器。

## 工作項目與狀態

### 1. Windows PAC 自動代理

**目標**
- 補測 Windows 自動代理指令碼（PAC）及設定變更。
- 修正 PAC 網址或代理參數改變後，仍沿用舊系統代理快照的問題。
- 驗證代理設定更新後連線池與 PAC 結果不會持續使用舊設定。

**已開始**
- 修正系統代理設定相同比對，將 `PACURL` 納入比較；即使 PAC 啟用狀態不變，PAC 網址變更也會套用新快照。
- 新增 Go 回歸測試，覆蓋 PAC URL、啟用狀態、HTTP／HTTPS 代理與 bypass 清單變更。

**驗收**
- Windows 10／11 切換 PAC 網址後，新請求使用新 PAC。
- PAC 切換為手動代理、直連或停用後，請求不再沿用舊代理。
- PAC 指令碼回傳 DIRECT、HTTP 與 HTTPS proxy 時，連線結果正確。
- 既有 bypass 規則及 localhost 直連行為不回歸。

### 2. 黃豆及其他片源：播放量為 0 時隱藏

**目標**
- 播放量為 0、空值或無有效數字時，不顯示播放量標籤。
- 不隱藏作品標題、集數、更新狀態或其他有效資訊。
- 舊版快取仍可讀取；更新資料時不得因新欄位缺值而把舊的有效資料錯誤清空。

**驗收**
- 黃豆及其他片源的 0 值播放量不顯示。
- 正數播放量正常顯示，原有格式與繁體中文用語保持一致。
- 舊版快取（包含既有版本化快取與舊格式）讀取正常。
- 新舊資料合併時，0 值視為「沒有可顯示的播放量」，不覆蓋仍有效的舊值；明確的來源資料更新規則另以測試固定。

### 3. Windows 桌面自動連播：控制列及暫停圖示閃現

**目標**
- 修復自動切換下一集、播放狀態短暫變化時，控制列或暫停圖示不必要地閃現。
- 保留使用者主動操作時正常顯示控制列。
- 不改動 Android TV 已有控制列顯示政策。

**驗收**
- Windows 自動連播、預載入接手、播放初始化及短暫 buffering 期間，控制列不閃現。
- 暫停圖示只在真實播放狀態需要時顯示，不因短暫事件反覆切換。
- 使用者移動滑鼠、按快捷鍵或點擊播放器後，控制列仍正常出現。
- 播放進度、音量、全螢幕及下一集切換不回歸。

### 4. iPhone Duo 適配

**目標**
- 使用 iOS 27.2 SDK／Xcode 27.2 作為本版 iPhone Duo 建置與測試基準。
- 依可用視窗尺寸自適應外螢幕、內螢幕及方向變化，不以固定機型尺寸寫死版面。
- 檢查狀態列、系統工具列、Safe Area、導覽列、海報格、搜尋、詳情與播放器。
- 保持既有 iPhone 與 iPad 相容。

**開發注意**
- Apple 指出 iOS 27 SDK 起 App 會隨 iPhone Duo 內外螢幕動態調整；iOS 27.1 SDK 或更新版本可使用完整顯示區域並配合垂直排列的系統工具列。iOS 27.2 符合此條件。
- 先檢查目前 Flutter 版面、方向控制及 iOS 專案設定，再決定必要的原生橋接；不新增依賴未公開 API 的裝置型號判斷。

**驗收**
- iPhone Duo 外螢幕、展開內螢幕、旋轉及開闔切換時，版面重新配置而非拉伸或裁切。
- 播放器在尺寸改變時不重新初始化、不重置播放進度。
- 系統狀態列／工具列出現在不同邊緣時，內容與操作不被遮擋。
- 一般 iPhone、iPad 的既有直向／橫向行為維持正常。
- 使用 Xcode Device Hub 的 iPhone Duo 模擬器測試各姿態；若 CI runner 未提供對應 Xcode／模擬器，需明確標示未完成的實機／模擬器驗收。

### 5. 跨平台區域網路自動同步

**既有基礎**
- 專案已有 `LanController`、裝置發現與配對、憑證 pinning、區域網路 TLS、差異同步、衝突保留及播放交接流程。
- 現有同步記錄涵蓋收藏、觀看狀態與續播進度；目前介面分開呈現「裝置互聯」及「自動同步」開關。

**本版目標**
- 以「區域網路自動同步」單一總開關控制裝置發現、配對與自動同步，不提供收藏、觀看紀錄、播放進度等各資料類別的獨立開關。
- 關閉總開關時，同時停用區域網接收服務與自動同步；舊版分離設定（enabled／autoSync）會合併為一個有效狀態，避免舊設定造成背景仍啟動接收服務。
- 已授權裝置在同一區域網路內自動發現、連線及同步；未授權裝置不得取得資料。
- 盤點帳號與密碼驗證資料的儲存格式及同步必要性。不得傳輸明文密碼；若確實需要跨裝置同步驗證資料，必須先定義可撤銷、可驗證、加密傳輸及本機安全儲存方案。
- 保留現有衝突偵測、合併與使用者切換隔離；不同使用者的資料不可交叉同步。

**驗收**
- Windows、macOS、iOS、Android／Android TV 可在已授權條件下互相同步。
- 首次配對需明確授權；後續自動同步不應要求每次手動確認。
- 中斷、離開前景、切換使用者、鎖定帳號或取消同步時，不提交不完整資料。
- 同一筆資料雙端修改時保留衝突，不靜默覆蓋。
- 不同步明文密碼、Token 或裝置私鑰；安全方案未通過審查前，不擴大帳號憑證同步範圍。

### 6. PlaybackSession／雙播放器預載架構研究

**既有基礎**
- 專案已有 `PlaybackPreloader`，可預先取得下一集的播放計畫／媒體資料，並管理 session 釋放、有效期限與取消。
- 本項先研究現有播放器生命週期及預載流程，不代表立即啟用第二個解碼器或播放器實例。

**研究內容**
- 設計 PlaybackSession 的狀態、資源所有權、取消、錯誤恢復及釋放時機。
- 比較單播放器預載與雙播放器預載的啟播延遲、記憶體、CPU／GPU、硬體解碼器資源、音訊焦點與音畫同步。
- 分別評估 Windows MPV、Android TV 現行播放器路徑、iOS 播放路徑的限制。
- 制定效能門檻及失敗時回退到現有單播放器流程的策略。

**驗收**
- 先交付架構文件、狀態圖、風險清單及可重現的效能測試結果。
- 雙播放器方案只有在目標裝置通過記憶體、解碼器數量、音訊、音畫同步及連續播放測試後，才另行提案實作。
- 本階段不得直接重寫或替換現有播放器核心。

## 開發與發布原則

- 先修復可獨立驗證的既有問題，再進行介面與同步功能。
- 每項修復需有對應單元／回歸測試；涉及平台行為者需補平台測試。
- `dev/v1.0.3` 的 CI 建置 Android、Windows、macOS、iOS 四平台，但不發布正式 Release。
- 不以 CI 編譯成功取代 Windows、Android TV 及 iPhone Duo 的實機／模擬器播放驗收。
- 1.0.3 版本號及正式建置號於準備候選版時統一更新；正式 Release 前不覆蓋 1.0.2 標籤或附件。
