# D TV 1.0.8 候選版

**狀態：候選版開發中，尚未正式發布**

- 基準版本：D TV 1.0.7（`v1.0.7`）
- 候選版本號：`1.0.8+1674`
- 開發分支：`release/v1.0.8-candidate`
- 本版核心方向：完成 MissAV／SupJav 的原生片源體驗，優先改善作品列表海報、詳情海報、圖片載入及播放解析可靠性。

本文件是 1.0.8 的範圍與驗收規格，不代表下列功能已經完成。每項功能須以程式修改、回歸測試及實際平台驗收結果更新狀態。

## 1. MissAV／SupJav 原生片源完整度

### 目錄、分類與搜尋
- 檢查並修正分類列表、分頁續載及搜尋結果，確認每筆作品都有穩定的作品識別碼與可用詳情路徑。
- 解析網站實際使用的列表資料欄位，包括延遲載入圖片欄位；不得只依賴單一可能變動的 HTML 屬性。
- 連結需以實際回應網址及重新導向後的網址為基準，正確處理絕對網址、相對網址及語系路徑。
- 切換分類、搜尋條件或片源時，不得把上一個片源的作品或海報混入目前結果。

### 作品列表與詳情海報
- 修正列表卡片海報無法顯示、空白或錯誤圖片的情況。
- 修正作品詳情頁主海報與其他圖片欄位的解析。
- 優先使用該片源提供的原始圖片；只有原始圖片確實不可用時，才依既有備援規則處理。
- 依網站實際需求設定圖片 Referer、處理重新導向與圖片主機；不可把頁面網址誤當成圖片網址。
- 圖片載入失敗及快取失敗需能重新嘗試；不得因暫時性的 403、404、逾時或空回應永久快取錯誤結果。
- 修正範圍以 MissAV／SupJav 可重現問題為主，不因單一站點問題大幅重寫所有片源的全域海報架構。

### 播放解析
- MissAV：依實際播放頁與重新導向後網址解析播放器資料，支援必要的相對 HLS 位址及站方實際提供的播放資料格式。
- SupJav：依播放器宣告的來源順序解析 FST／HLS，正確處理絕對與相對網址；只有播放器明確標示為 HLS 的無副檔名或特殊副檔名來源才可作為 HLS 播放清單。
- 保留各伺服器、各播放來源的失敗原因，讓使用者能分辨沒有播放網址、來源格式不支援、連線錯誤或站方拒絕請求。
- 若站方回傳 HTTP 403、要求互動式驗證或限制目前裝置存取，必須如實回報並保留診斷；不可將遭拒絕的請求假裝成已支援播放，也不可假設能繞過站方限制。

## 2. 既有片源與使用者資料相容性

- 保留 MissAV、SupJav 現有片源識別碼，不造成舊版設定中的啟用狀態或排序遺失。
- 保留進階片源權限、管理員解鎖流程、手動排序與「限制級」標籤規則。
- 不改動紅果、韓小圈、鬼片及多多追劇已正常的目錄、海報、收藏、觀看紀錄與播放流程。
- 不因片源暫時失效、停用或重新啟用而清除收藏、觀看紀錄或播放進度。

## 3. 跨平台一致性

- MissAV／SupJav 共用原生 Provider 與 Flutter 呈現路徑，避免只在單一平台修正。
- Android／Android TV、Windows、macOS、iOS 均需驗證列表海報、詳情海報、搜尋、分類及播放流程。
- Android TV 需額外驗證遙控器焦點、詳情頁進出、播放按鈕與返回鍵。
- 不改變 iOS 不提供投放入口的既定設計。

## 4. 自動化測試與驗收

### Go／Flutter 測試
- Go：`go test ./...`。
- Flutter：執行完整測試套件及標準版主要片源測試。
- 針對 MissAV／SupJav 增加去識別化 fixture，覆蓋分類列表、分頁、搜尋、詳情、海報網址、重新導向、相對 HLS、播放器來源順序及錯誤回應。
- 測試不得依賴即時第三方網站才能通過；即時站點驗證另列為人工／整合驗收，且需記錄測試日期與結果。

### 四平台建置
- Android Universal APK：驗證簽章、套件識別與 ARM64／ARMv7／x86_64 三種 ABI。
- Windows x64：Portable ZIP 建置及啟動檢查。
- macOS：Universal DMG 建置。
- iOS：未簽章 IPA 建置及 iPhone Duo 模擬器建置／啟動檢查。
- 發布前產生四平台正式附件及 `SHA256SUMS.txt`。

### 實機驗收
每個片源需分別驗證：
1. 進入目錄及切換分類。
2. 列表海報正常載入，捲動時不出現持續空白或重複錯誤圖片。
3. 搜尋結果正確，點選後可載入作品詳情。
4. 詳情海報正確。
5. 播放來源可解析並實際起播；播放失敗時呈現可辨識的原因。
6. Android TV 遙控器可操作，且其他平台沒有回歸。

未取得某平台的實機時，需明確標示為 CI 建置或模擬器驗證，不可描述成該裝置實測通過。
